## 1. 逐个项目拆解

### 1.1 mini-swe-agent：先读它，理解本质

- 核心文件：[agents/default.py](repos/mini-swe-agent/src/minisweagent/agents/default.py)（190 行），[environments/local.py](repos/mini-swe-agent/src/minisweagent/environments/local.py)
- **只有一个工具：bash**。模型每轮输出一个 bash 代码块，环境执行后把结果回填。改文件靠 `sed` / `cat <<EOF`。
- 三个抽象：`Agent`（循环）、`Model`（LLM）、`Environment`（执行），互相解耦。这正是你需要的"执行目标"抽象的雏形：`LocalEnvironment` 与 `DockerEnvironment` 实现同一个 `execute()`。
- 停止条件：步数上限、费用上限、墙钟时间上限、连续格式错误上限。
- 完成信号：模型输出特殊字符串 `COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT`。
- 每一步都把完整轨迹（trajectory）存成 JSON，方便调试和评测。
- 进程超时时**杀掉整个进程组**，避免孤儿进程（`start_new_session` + `killpg`）。

**启示**：agent 的本质就是 "循环 + 执行 + 回填"。先用 200 行写出能跑的版本，再逐步加功能。

### 1.2 OpenCode：和你的架构最接近

**架构**：后台服务（server）+ 多个客户端（TUI / 桌面 Electron / Web），通过 HTTP API + SSE 事件流通信。

| 模块 | 位置 | 要点 |
|---|---|---|
| 分层规则 | [AGENTS.md](repos/opencode/AGENTS.md) | Schema → Core/Protocol → Server；Client 只依赖 Schema 和 Protocol，**不依赖 Core**。客户端与 agent 核心彻底解耦 |
| 事件推送 | [server/src/event-feed.ts](repos/opencode/packages/server/src/event-feed.ts) | 每个订阅者一个有界队列（4096），满了就断开该订阅者，不拖慢其他订阅者；可按事件类型过滤 |
| 配对 | [server/src/pairing.ts](repos/opencode/packages/server/src/pairing.ts) | 一次性配对码，16 字节随机数，5 分钟过期，用一次即作废 |
| 认证 | [server/src/auth.ts](repos/opencode/packages/server/src/auth.ts) | 会话 token = `过期时间.HMAC签名`，签名密钥由服务密码派生。**改密码即吊销所有设备**。比较时用 `timingSafeEqual` 防时序攻击 |
| 远程访问 | [cli/src/commands/handlers/pair.ts](repos/opencode/packages/cli/src/commands/handlers/pair.ts)、[services/remote-tunnel.ts](repos/opencode/packages/cli/src/services/remote-tunnel.ts) | `opencode pair --remote`：后台服务主动连隧道服务获得公网地址，终端打印二维码（含配对码 + 地址），手机扫码即连。断线指数退避重连 |
| 主循环一步 | [core/src/session/runner/step.ts](repos/opencode/packages/core/src/session/runner/step.ts) | **模型流式输出中一出现工具调用就立刻并行执行**，不等整个回复结束；每步开始前异步拍文件快照；上下文超长报错时自动压缩再重试 |
| 快照 | [core/src/snapshot.ts](repos/opencode/packages/core/src/snapshot.ts) | 基于 git 的文件快照，支持 diff 和按文件恢复，实现"撤销这一步" |
| 输出截断 | [core/src/tool-output.ts](repos/opencode/packages/core/src/tool-output.ts) | 上限 2000 行 / 50KB；超出部分**写入文件并把路径告诉模型**，模型需要时再分段读取 |
| 编辑工具 | [core/src/tool/plugin/edit.ts](repos/opencode/packages/core/src/tool/plugin/edit.ts) | old/new 精确替换；匹配前规范化"智能引号""长破折号""全角空格"；处理 CRLF 和 BOM；有逐行宽松匹配兜底 |
| 权限 | [core/src/permission.ts](repos/opencode/packages/core/src/permission.ts) | 规则 = `(action, resource 通配符, effect: allow/ask/deny)`，**最后一条匹配的规则生效**，默认 ask；deny 优先；无人值守时 ask 自动变 deny |
| 上下文压缩 | [core/src/session/compaction.ts](repos/opencode/packages/core/src/session/compaction.ts) | 结构化摘要模板；保留最近 N tokens 原文；**接近阈值时后台预先计算摘要**，到点直接替换；增量更新旧摘要而非重写 |
| 模型适配 | [packages/ai/src](repos/opencode/packages/ai/src) | 拆成 **protocols**（线协议：anthropic-messages、openai-chat、openai-compatible-chat、gemini…）和 **providers**（厂商：deepseek、moonshot、zai、alibaba、openrouter…）。一个 provider = 一个 protocol + base_url + 鉴权 + 默认参数 |
| SSH 密码 | [cli/src/ssh-askpass.ts](repos/opencode/packages/cli/src/ssh-askpass.ts) | 调用系统 `ssh`，通过 `SSH_ASKPASS` 把密码提示转发给 UI，由用户在界面里输入 |

**注意**：OpenCode 全量使用 Effect 框架，代码抽象层次高，初读门槛较大。建议只看设计思路，不必照搬写法。

### 1.3 Cline：Hub 守护进程 + SSH 远程环境

- 架构文档：[sdk/ARCHITECTURE.md](repos/cline/sdk/ARCHITECTURE.md)（1300+ 行，非常值得通读）
- 分层：`shared → llms → agents → core → apps`
  - `agents`：**无状态**的循环，不负责存储和生命周期
  - `core`：有状态的编排，包括会话、持久化、配置、Hub 服务
- **Hub 守护进程**：一台机器上一个 daemon，服务所有客户端（CLI、VS Code、桌面端）。客户端可以 attach/detach 同一个会话而不打断运行，这和你"电脑开始、手机接续"的需求完全一致。CLI 发现没有 Hub 时会自动拉起一个 detached daemon。
- 桌面端示例：Tauri + Next.js + Bun sidecar，后端通过 `ws://127.0.0.1:3126/transport` 提供服务。
- 主循环：[agents/src/agent-runtime.ts](repos/cline/sdk/packages/agents/src/agent-runtime.ts) 第 839 行起。值得学的处理：
  - 模型没调用完成工具（`submit_and_exit`）就停下时，插入**提醒消息**让它继续
  - 输出被 max_tokens 截断时自动恢复续写
  - 空回复、未知结束原因、内容过滤分别给出明确错误
  - 每个阶段都发事件：`turn-started`、`message-added`、`turn-finished`、`run-finished`
- **SSH 远程环境**：[core/src/remote/remote-environments.ts](repos/cline/sdk/packages/core/src/remote/remote-environments.ts)
  - 不是"把每条命令通过 SSH 发过去"，而是**把 helper 程序上传到远程机器，在远端启动一个 Hub**（只监听 loopback），再用 `ssh -L` 转发到本地端口，客户端像连本地 Hub 一样连它。和 VS Code Remote-SSH 是同一个思路。
  - 上传按内容哈希寻址，避免重复上传。
  - 使用系统 `ssh` 命令，只支持密钥（`identityFile`），**不支持密码登录**。
- 工具名单（部分）：`read_file(s)`、`editor`、`apply_patch`、`run_commands`、`search_codebase`、`ask_question`、`spawn_agent`、`submit_and_exit`、`team_*`（多 agent 协作）。

### 1.4 Goose：Electron 桌面 + P2P 中继 + 安全

- 桌面端：[ui/desktop](repos/goose/ui/desktop)，Electron + React；后端是 Rust 进程（`goosed`），两者用 **ACP（Agent Client Protocol）** 通信。
- **远程控制，方案一：goose-roaming**，见 [crates/goose-roaming/src/lib.rs](repos/goose/crates/goose-roaming/src/lib.rs)
  - 基于 iroh（QUIC P2P），**不开端口**，打不通直连时走中继，中继可以自建
  - 身份 = ed25519 密钥对，**没有 bearer token**，授权完全基于"对方公钥是否在我的信任列表"（TrustBook）
  - 连接卡片（ConnectionCard）= 公钥 + 中继地址 + 指纹，可公开分享，本身不授予任何权限
- **远程控制，方案二：gateway**，见 [crates/goose/src/gateway](repos/goose/crates/goose/src/gateway)：通过 Telegram 机器人加配对码，从手机上和 agent 对话。
- 安全模块 [crates/goose/src/security](repos/goose/crates/goose/src/security)：
  - [patterns.rs](repos/goose/crates/goose/src/security/patterns.rs)：危险命令正则库，按风险等级（Low 到 Critical）和类别（文件破坏、远程代码执行、数据外泄、系统修改…）分类
  - 提示注入扫描器、出站流量检查（egress inspector）
- 权限：[permission/permission_judge.rs](repos/goose/crates/goose/src/permission/permission_judge.rs) **让 LLM 判断一个工具调用是否只读**，只读的自动放行（smart approve 模式）。
- 重复检测：[tool_monitor.rs](repos/goose/crates/goose/src/tool_monitor.rs) 统计"同名同参数"工具调用的连续次数，超限就打断，防止死循环。

### 1.5 OpenHands software-agent-sdk：事件日志与 Workspace 抽象

> OpenHands 主仓库现在只包含前端（Agent Canvas），agent 核心、事件和协议都已迁到 software-agent-sdk。

- **Workspace 抽象**：[workspace/base.py](repos/software-agent-sdk/openhands-sdk/openhands/sdk/workspace/base.py) 定义了 `execute_command`、`file_upload`、`file_download`、`git_changes`、`git_diff`、`pause`、`resume`。实现包括 local、docker、remote、cloud 等。**这就是你要的 Target 抽象**，可以直接参考接口设计。
- **只追加事件日志**：所有状态变化都是一个 Event（带 `source` 和 `timestamp`）。能转成 LLM 消息的事件继承 `LLMConvertibleEvent`。
- **上下文压缩不删数据**：[context/condenser/README.md](repos/software-agent-sdk/openhands-sdk/openhands/sdk/context/condenser/README.md)
  - 压缩时追加一个 `Condensation` 事件（类似墓碑标记），记录"忘掉哪些事件、插入什么摘要"
  - `View` 类把事件日志投影成"当前发给模型的消息"
  - 策略：把前一半事件替换成摘要，后一半保留原文
  - 软触发（接近上限，失败了下一步再试）与硬触发（已经超限，必须整体重置）分开处理
  - **对多端同步极其友好**：手机端拿到的是完整日志，任何时刻都能重放
- **风险分级 + 确认策略**：[security/confirmation_policy.py](repos/software-agent-sdk/openhands-sdk/openhands/sdk/security/confirmation_policy.py)
  - 模型调用工具时**自己填一个 `security_risk` 字段**（LOW / MEDIUM / HIGH）
  - 策略：`AlwaysConfirm`、`NeverConfirm`、`ConfirmRisky(threshold=HIGH)`
  - 还有基于 shell AST 解析的分析器、LLM 分析器，可以组合使用（ensemble）
- **Critic（评审者）**：[critic/base.py](repos/software-agent-sdk/openhands-sdk/openhands/sdk/critic/base.py) 对结果打分，低于阈值就自动让 agent 重做（迭代精炼）。

### 1.6 Aider：Repo Map 与编辑格式

- **Repo Map**：[aider/repomap.py](repos/aider/aider/repomap.py)
  - 用 tree-sitter 提取每个文件的定义和引用（tags）
  - 构建"文件引用图"，用 **PageRank** 排序，当前对话中提到的文件权重更高
  - 在 token 预算内渲染出"最重要的符号签名"，作为代码库概览发给模型
  - 解决的问题：大仓库装不进上下文，又不想让模型盲目 grep
- **多种编辑格式**：[aider/coders/](repos/aider/aider/coders) 下有 whole file、SEARCH/REPLACE 块、unified diff、patch 等。不同模型擅长的格式不同，可按模型配置。
- **模糊匹配兜底**：[search_replace.py](repos/aider/aider/coders/search_replace.py) 依次尝试精确匹配、忽略空行、相对缩进、diff-match-patch、git cherry-pick 等策略。
- Prompt 范本：[editblock_prompts.py](repos/aider/aider/coders/editblock_prompts.py)。

### 1.7 Codex：沙箱与审批是两个独立维度

- **沙箱策略**（能做什么）与**审批策略**（何时问人）**正交**：
  - SandboxPolicy：`ReadOnly`、`WorkspaceWrite`、`DangerFullAccess`、`ExternalSandbox`（网络访问可单独开关）
  - AskForApproval：`untrusted`（除白名单外都问）、`on-request`（模型自己决定何时请求）、`granular`（细粒度）、`never`
  - 定义见 [app-server-protocol/src/protocol/v2](repos/codex/codex-rs/app-server-protocol/src/protocol/v2)
- OS 级沙箱：macOS Seatbelt、Linux bwrap/landlock（[linux-sandbox](repos/codex/codex-rs/linux-sandbox)），以及 **Windows 沙箱**（[windows-sandbox-rs](repos/codex/codex-rs/windows-sandbox-rs)）。
- **app-server**：JSON-RPC 协议，供 VS Code 插件和桌面端使用。概念模型是 thread → turn → item。文档里有一点值得注意：**待审批请求在客户端重连后会重放**（[app-server/README.md](repos/codex/codex-rs/app-server/README.md)），这正是手机断线重连需要的。
- `apply_patch`：自定义 patch 格式和流式解析器（[apply-patch/src](repos/codex/codex-rs/apply-patch/src)）。

### 1.8 Gemini CLI：Windows 与健壮性细节

- **Windows 中文乱码**：[services/shellExecutionService.ts](repos/gemini-cli/packages/core/src/services/shellExecutionService.ts) 第 101–116 行，在命令前加 `chcp 65001`（PowerShell 和 cmd 写法不同）。
- **PTY**：使用 `@lydell/node-pty`，在 Windows 上强制走 ConPTY（避免回退到 WinPTY），支持交互式命令。
- **循环检测**：[services/loopDetectionService.ts](repos/gemini-cli/packages/core/src/services/loopDetectionService.ts)，相同工具调用连续 5 次或相同内容重复 10 次即判定循环，另外还有一个 LLM 辅助判断。
- **偷懒检测**：[tools/omissionPlaceholderDetector.ts](repos/gemini-cli/packages/core/src/tools/omissionPlaceholderDetector.ts) 检测模型写的 `// ... rest of code` 之类的占位符并拒绝。

### 1.9 Happy：手机 + 中继 + 端到端加密的完整实现

- 仓库结构：[packages](repos/happy/packages) 下有 `happy-app`（Expo，iOS/Android/Web 一套代码）、`happy-server`（中继服务器）、`happy-cli`（电脑端）、`happy-wire`（协议定义）、`happy-server-self-host`（自部署）。
- 文档非常完整，重点读这三篇：
  - [docs/encryption.md](repos/happy/docs/encryption.md)：**服务器看不到用户内容**。旧方案用 tweetnacl secretbox（XSalsa20-Poly1305），新方案为每个会话或每台机器生成一个 AES-256-GCM 数据密钥，再用 `tweetnacl.box`（临时密钥对）包装分发。二进制布局有版本字节，方便以后升级。
  - [docs/realtime-sync-and-rpc.md](repos/happy/docs/realtime-sync-and-rpc.md)：Socket.IO 三种连接作用域：**user**（手机/网页）、**session**（一个运行中的会话）、**machine**（一台电脑的 daemon）。房间模型 `user:<id>:session:<sid>` 用于广播；RPC 通过房间 `rpc:<userId>:<method>` 路由到具体设备；目标暂时掉线时稍等重连再失败。
  - [docs/api.md](repos/happy/docs/api.md)：**账号即密钥对，没有密码**。登录 = 用私钥签 challenge；新终端接入 = 终端出示公钥（二维码），已登录的手机批准，并把密钥用终端公钥加密后发回去。
- 设计差异：Happy 的服务器**会存储加密后的消息**（Postgres），所以电脑离线时手机也能浏览历史；而 OpenCode / Cline 的方案是服务器只转发。
- 权限模式：`default | acceptEdits | plan | read-only | safe-yolo | yolo`，手机端可以随消息切换（[docs/permission-resolution.md](repos/happy/docs/permission-resolution.md)）。
- 手机可以通过 machine 作用域的 RPC **在电脑上新建会话**，而不只是接续已有会话。

## 2. 按你的需求横向对比

### 2.1 Agent 主循环

| 做法 | 来源 | 建议 |
|---|---|---|
| 单工具 bash + 文本解析 | mini-swe-agent | 入门练手 |
| 原生 tool calling，回复结束后串行执行 | 多数项目 | **MVP 采用** |
| 流式输出中工具调用就绪即并行执行 | OpenCode | 第二阶段优化 |
| 完成工具 + 未调用时提醒 | Cline（`submit_and_exit`） | 采用，能减少"假装完成" |
| 步数、费用、时间上限 | mini-swe-agent、Cline | 采用 |
| 重复调用检测 | Goose、Gemini CLI | 采用 |

### 2.2 文件编辑

**结论：用 `edit(path, old_string, new_string, replace_all?)` 精确替换**（OpenCode、Gemini CLI、Cline 都是这样），再加三层兜底：
1. 规范化匹配：引号、破折号、全角空格、CRLF、BOM（参考 OpenCode `edit.ts`）
2. 逐行宽松匹配：忽略行尾空白和缩进差异（参考 OpenCode、Aider）
3. 仍失败时，用便宜模型修正 old_string（参考 Gemini CLI `llm-edit-fixer.ts`）

另外检测占位符偷懒（Gemini CLI），每步前拍快照以便撤销（OpenCode `snapshot.ts`）。

### 2.3 上下文管理

| 能力 | 推荐参考 |
|---|---|
| 工具输出截断，超出部分落盘并返回路径 | OpenCode `tool-output.ts` |
| 事件日志 + 压缩标记 + View 投影 | OpenHands condenser |
| 结构化摘要模板、增量更新、后台预计算 | OpenCode `compaction.ts` |
| 代码库概览 | Aider repo map（进阶） |
| 项目说明文件（AGENTS.md） | 所有项目都支持，建议兼容 `AGENTS.md` |

### 2.4 权限与安全

推荐组合（取各家之长）：
1. **规则引擎**（OpenCode）：`(动作, 资源通配符) → allow/ask/deny`，deny 优先，默认 ask
2. **执行范围和审批时机分开**（Codex）：执行范围是只读、工作区可写或完全访问；审批时机是总是问、有风险才问或从不问
3. **风险分级**（OpenHands + Goose）：危险命令正则库，加上模型自报的 `security_risk`
4. **按来源区分**（你的特有需求）：手机发起的操作和 SSH 远程操作，默认更严格
5. **无人值守降级**（OpenCode）：没有客户端在线时，需要 ask 的操作要么挂起等待，要么直接拒绝；审批请求在客户端重连后重放（Codex）

### 2.5 执行目标与 SSH（重点）

调研中看到两种 SSH 方案：

| | 方案 A：远程执行（命令通过 SSH 发过去） | 方案 B：远程 agent（Cline / VS Code Remote 的做法） |
|---|---|---|
| 做法 | 本地 agent 通过 SSH exec 和 SFTP 操作远程机器 | 把 agent 服务上传到远端运行，SSH 端口转发连回来 |
| 远程依赖 | 无，只要有 sshd | 远端需要能运行你的程序（Node 或单文件二进制） |
| 性能 | 每次读写都走网络；grep 需要在远端执行 | 本地级别 |
| 实现难度 | **低** | 高（打包、上传、版本管理、跨平台） |
| 适合 | 运维、部署、改配置、查日志，**以及多台机器** | 在远端长期开发一个大项目 |

**建议：先做方案 A**，正好对应 Target 抽象（参考 OpenHands Workspace 接口）。方案 B 留到以后。

关于**密码登录**：调研的项目都不鼓励密码登录（Cline 只支持密钥，OpenCode 通过 askpass 让用户每次手动输入）。你的需求要保存密码，建议：
- 使用 `ssh2`（纯 JS 实现，原生支持 password、keyboard-interactive 和私钥认证），不依赖系统 ssh
- 密码存入系统钥匙串（Windows 凭据管理器），参考 Gemini CLI `keychainService.ts`、Goose 的 keyring 用法
- **首次连接时展示 host key 指纹并让用户确认，之后进行校验**
- 引导用户优先使用密钥：提供"一键生成密钥并安装到服务器"的功能，之后可以停用密码
- 密码**绝不能**进入模型上下文、日志或事件流

### 2.6 Daemon 与客户端协议

| 项目 | 传输 | 模型 |
|---|---|---|
| OpenCode | HTTP API + SSE | 会话 / 消息 / 事件 |
| Cline | WebSocket（Hub） | 命令/回复 + 事件流，客户端可 attach/detach |
| Codex | JSON-RPC（stdio / WebSocket） | thread / turn / item |
| Goose | ACP | 标准化的 Agent Client Protocol |
| Happy | Socket.IO | user / session / machine 三种作用域 + RPC |

**建议**：daemon 用 **WebSocket + JSON-RPC 风格**：
- 请求/响应：`session.create`、`session.send`、`session.abort`、`approval.reply`…
- 服务端推送：`event`（带**单调递增序号**）
- 重连：客户端带上 `lastSeq`，服务端补发缺失事件；未处理的审批请求重新推送
- 协议定义放在独立的 `protocol` 包，daemon、桌面端、手机端、网关共用（OpenCode 的分层规则）

### 2.7 手机端与云网关

| | OpenCode | Goose roaming | Happy | **你的方案（建议）** |
|---|---|---|---|---|
| 连接方式 | 隧道服务 | iroh P2P + 中继 | 自建中继服务器 | **自建 WebSocket 网关** |
| 电脑开端口 | 否 | 否 | 否 | 否（daemon 主动连网关） |
| 身份 | 密码派生 token | ed25519 公钥 | 公钥签名 | **设备密钥对 + 网关 token** |
| 配对 | 二维码 + 一次性码 | 交换连接卡片 | 二维码 + 手机批准 | **二维码 + 一次性码 + 交换公钥** |
| 端到端加密 | 是 | QUIC-TLS | 是（NaCl / AES-GCM） | **是（tweetnacl box / secretbox）** |
| 服务器存储内容 | 否 | 否 | 存密文 | **第一版不存**，第二版可选存密文 |

网关的路由模型直接借鉴 Happy：连接分 user / machine / session 三种作用域，以房间方式转发，RPC 按 `machineId` 路由。

### 2.8 多模型适配

参考 OpenCode 的 **protocol / provider 两层**：
- **protocol**（线协议，只写 3 个）：`anthropic-messages`、`openai-chat`（兼容格式，覆盖 DeepSeek、Qwen、Kimi、GLM、Ollama、vLLM、OpenRouter…）、`gemini`
- **provider**（配置）：`{ id, protocol, baseUrl, apiKey(钥匙串), headers, models: [{ id, contextWindow, maxOutput, supportsTools, supportsImages, supportsThinking, price }] }`
- 内部统一消息格式与流式事件（text-delta、reasoning-delta、tool-call、usage、finish）
- 按用途分配模型：主对话、子 agent、上下文压缩、标题生成、编辑修复、权限判断
- 容错：工具参数 JSON 修复（OpenCode `tool-input-repair.ts`）、可重试错误分类、上下文超长识别

### 2.9 桌面客户端

| 选项 | 例子 | 评价 |
|---|---|---|
| Electron + React | Goose、OpenCode desktop | **推荐**：全栈 TS，生态成熟，体积大 |
| Tauri + Web + sidecar | Cline desktop 示例 | 体积小，需要 Rust |

推荐 Electron。**daemon 必须是独立进程**（不要跑在 Electron 主进程里），桌面端关掉后任务照常运行。

### 2.10 Windows 注意事项（来自 Gemini CLI、mini-swe-agent）
- 命令前加 `chcp 65001`，或统一用 PowerShell 并设置 UTF-8 输出编码
- 用 node-pty（ConPTY）支持交互式命令
- 超时要杀整个进程树（Windows 上用 `taskkill /T /F`）
- 路径统一规范化，注意大小写不敏感
- 长进程放后台，提供"查看输出 / 停止"工具

│  ├ Session + 事件日志(SQLite) │   E2E 密文          │  └ (推送)        │       │          │

### 关键决策汇总

| 决策 | 选择 | 依据 |
|---|---|---|
| 语言 | TypeScript 全栈 | OpenCode、Cline、Gemini CLI、Happy 均为 TS；协议代码可以多端共享 |
| 运行时 | Node.js 22+（不用 Bun，Windows 更稳） | Cline 用 Node 作运行时 |
| 框架 | 不用 Effect / LangChain，手写 | 你的目标是掌控细节；Effect 学习成本高 |
| 进程模型 | 独立 daemon + 多客户端 | OpenCode、Cline Hub、Codex app-server |
| 状态存储 | 只追加事件日志（SQLite）+ 压缩标记 + View | OpenHands |
| 编辑 | 精确替换 + 三层兜底 + 快照 | OpenCode、Gemini CLI、Aider |
| 权限 | 规则引擎 + 风险分级 + 按来源区分 | OpenCode、Codex、OpenHands、Goose |
| SSH | 方案 A（ssh2 + 钥匙串），工具通过注入的 Operations 接口执行；以后可升级为方案 C（远端微型 daemon） | OpenHands Workspace、pi `Operations`、Kimi `kaos`、pi-env（见续篇） |
| 远程 | 先接 IM 机器人（飞书/微信），再做自建网关 + 设备密钥对 + E2E | Proma、Hermes、Happy、OpenCode、Goose（见续篇） |
| Prompt cache | 架构原则：system prompt 分段增量更新，对话中途不重写前缀 | pi、Hermes、dsh（见续篇） |
| 桌面 | Electron + React | Goose、OpenCode |
| 手机 | PWA（复用 React 组件），以后再考虑 Expo | Happy 用 Expo |

### 建议的 monorepo 结构

```
packages/
  protocol/     # 事件、命令、消息类型（所有端共享）
  llm/          # 模型适配：protocols/ + providers/

  tools/        # read/edit/write/bash/grep/glob/todo/ask
  targets/      # local / ssh
  core/         # 会话、事件日志、权限、压缩、配置、钥匙串
  daemon/       # WebSocket 服务 + 网关客户端
  gateway/      # 云端网关
  ui/           # 共享 React 组件
  desktop/      # Electron
  mobile/       # PWA
```
